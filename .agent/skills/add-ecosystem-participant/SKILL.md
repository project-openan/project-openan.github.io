# Add Ecosystem Participant

将新加入 OpenAN 的组织添加到首页 **Ecosystem Participants**，并按用户选择发布加入新闻。

## 输入

- **必填**：组织名称。用户未提供时先询问，不要猜测。
- **可选**：用户上传的组织 Logo 文件、组织全称或简称、加入日期。
- 除组织名称外，不要为了开始流程而要求用户补齐可从公开资料核实的信息。

## 工作流程

### 1. 优先读取组织登记信息并获得明确确认

1. **首先读取 `https://github.com/project-openan/governance/issues/4` 的评论，再做任何通用网络搜索。** 按输入的组织全称或简称找到匹配评论，并记录评论的永久链接；使用 GitHub API 时获取全部评论分页，不要只看 Issue 正文或最新一条评论。
2. 优先采用匹配评论中的信息：
   - `Organization/Company`：组织官方名称。
   - `Website`：待用户确认的组织官网。
   - `Logo Display`：Logo 展示许可及 Logo 图片或品牌页面地址。
   - `Country`、`Description of Use or Contribution`：新闻写作时可核实的背景信息；计划或意向不得写成已经完成的成果。
3. 找不到匹配评论，或评论中的字段缺失、链接失效、内容矛盾或无法确认对应组织时，再通过组织官网和可靠公开来源补充。打开候选页面核实，而不是只依据搜索摘要；注意区分总公司、子公司和同名组织。
4. 向用户展示组织官方名称、官网 URL、Logo 来源和 Issue 评论链接，请用户明确确认。**即使 Issue 已提供官网，也必须经过用户确认；确认前不得修改网站文件。** 存在多个匹配评论或信息不一致时列出差异，不要自行选择。
5. 官网确认后，询问用户：**“是否同时发布 `<组织名称>` 加入 OpenAN 的新闻？”**。可在确认官网的同一轮提问中一并询问，但必须分别记录两个答案。
   - 选择“否”：只完成 Logo 添加，不创建或修改任何新闻文件。
   - 选择“是”：完成 Logo 添加后，继续执行第 4 节。
6. 不公开或复制评论中的联系人姓名、邮箱等 `Contact Info`，除非用户明确要求且确有必要。

### 2. 准备组织 Logo

先检查 `index.html` 的 `.partner-grid` 和 `src/images/participants-logo/`，确认该组织尚未存在，并沿用当前文件命名及展示方式。发现重复时停止新增并向用户说明。

如果匹配 Issue 评论存在，检查其中的 `Logo Display`：只有明确为 **Yes** 且没有附加待讨论条件时，才可据此展示 Logo；如果为 **No**、授权不清或仍需线下讨论，暂停发布并请用户确认，不得把“附有 Logo 链接”视为展示授权。

#### 用户已上传 Logo

- 使用用户提供的文件，保持原始宽高比，不拉伸、不重绘商标；当前请求中用户明确上传的文件优先于网络素材。
- 转换为适合网页的格式时保留透明背景，确保文件真实格式与扩展名一致。

#### 用户未上传 Logo

- **优先使用匹配 Issue 评论中 `Logo Display` 给出的素材。** 如果链接是直接图片地址，下载并验证；如果链接是官网或品牌页面，打开页面并定位其中的实际 Logo，不要把网页 URL 当作图片地址。
- Issue 未提供 Logo、素材链接失效，或素材不是适合展示的横版时，再从组织官网页眉、官方品牌或媒体资源页寻找合适的**横版 Logo**，其次才使用可信的品牌资源库。不要拉伸非横版素材。
- 优先选择带透明背景的横向 PNG 或 WebP；官方 SVG 可在保持矢量内容和宽高比的前提下转换。不要使用方形图标、竖版组合标志、截图或低清晰度缩略图代替横版 Logo。
- 检查 Logo 在网站深色背景上的可读性。不要通过生成式绘图臆造或重新设计组织商标。
- 记录 Issue 评论链接和实际素材来源 URL。无法确认素材对应该组织或找不到合适横版时，向用户说明并请求提供，不要随意替代。

将最终文件保存到：

```text
src/images/participants-logo/<organization_slug>.<ext>
```

其中 `<organization_slug>` 使用小写单词加下划线，扩展名必须与真实图片格式一致。保存后实际打开图片检查内容与尺寸，不要仅凭下载成功判断素材可用。

### 3. 将 Logo 追加到列表末尾

在 `index.html` 的 `.partner-grid` 中，把下面这一项插入**最后一个现有组织之后、容器结束标签之前**。不要重排或改写其他组织：

```html
<a href="CONFIRMED_OFFICIAL_URL" target="_blank" rel="noopener noreferrer"><img class="partner-logo" src="./src/images/participants-logo/ORGANIZATION_SLUG.EXT" alt="ORGANIZATION_SHORT_NAME" /></a>
```

要求：

- `href` 必须使用用户已确认的官网。
- `alt` 使用准确、简洁的组织名称。
- 复用现有 `.partner-logo` 样式；正常横版 Logo 不增加组织专属 CSS。只有实际预览发现明显尺寸异常时才做最小调整。
- 保持相对路径、缩进和单行结构与其他 Logo 一致。
- 不修改免责声明，不更新未经要求的成员统计或其他页面。

### 4. 仅在用户同意后发布加入新闻

用户同意发布新闻时，**必须调用 `openan-member-join-news` 技能生成新闻，其路径为 `.agent/skills/openan-member-join-news`**。不要在本技能中重新实现或另写一套新闻生成规则。

向该技能提供 Issue 评论永久链接、已确认的组织官方名称、官网、最终 Logo 文件和发布日期；用户未指定日期时使用当前日期。同时将评论中的 `Country`、`Description of Use or Contribution` 作为公开事实来源传入，但保留其中的计划或意向语气。新闻详情页、封面、`news.html` 卡片同步、写作规范和本地预览均遵循 `openan-member-join-news` 的要求。

该技能返回后，检查其产出是否完整，并在最终汇报中列出新闻相关文件与验证结果。用户不同意发布新闻时，不得调用该技能。

### 5. 验证与交付

- 检查新增 HTML 的链接、图片路径、转义和日期；确认所有本地资源存在且图片可打开。
- 从仓库根目录启动本地静态服务器，预览 `index.html#participants`；如发布新闻，同时预览新详情页和 `news.html`。确认新 Logo 位于最后、比例正常、链接指向已确认官网，新闻封面与卡片正常显示。验证后关闭服务器。
- 查看最终 diff，确保只包含本任务需要的文件改动，没有覆盖用户已有修改。
- 用与用户相同的语言汇报：确认的官网、Logo 来源、修改文件、验证结果，以及用户选择的新闻发布状态。
- 未经用户另行明确要求，不执行 `git commit`、`git push` 或创建 PR。
